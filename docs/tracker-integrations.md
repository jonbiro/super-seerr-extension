# Trakt, Simkl and JustWatch

Super Seerr adds request controls to supported Trakt, Simkl and JustWatch title pages. The flyout also offers **Explore this title** links, a streaming region selector for JustWatch, and **Copy title** for use in Simkl search. These links open the provider's website; a search result still needs to be checked for the right title.

## Connect a Trakt or Simkl account

Open **Settings → Trakt & Simkl watchlists**. Each provider has its own application Client ID and connection. You supply your own registered application; Super Seerr does not include a shared application registration.

1. In Settings, use **Copy callback URL** for that provider (or select the read-only field) and copy the **Callback URL for this browser**. It is generated by the browser's `identity.getRedirectURL()` API. Use the displayed value for this installed extension and browser profile; another browser or extension installation can have a different callback.
2. Follow **Register a Trakt app** to the [Trakt developer portal](https://developer.trakt.tv/apps), or **Register a Simkl app** to [Simkl developer settings](https://simkl.com/settings/developer/). Sign in to the provider yourself. Trakt's [registration guide](https://developer.trakt.tv/docs/create-an-app) describes its current developer-account requirements.
3. Register a **public browser application** and paste the callback into its redirect URI field **exactly**, including its path and trailing slash if present. For Simkl, choose **Mobile, desktop & browser apps** with **AUTH V2**. Existing Simkl V1 client IDs cannot be used with the V2 endpoints.
4. Paste the application's public **Client ID** into its Settings card and choose **Save app**. A client secret is not needed; do not paste one into this field.
5. Choose **Connect Trakt** or **Connect Simkl**, approve the browser's optional access prompt, and complete sign-in and consent on the provider's page. Cancelling permission or consent leaves the account disconnected.

Connections use OAuth authorization code flow with **PKCE S256**. Simkl is asked for `media:read`; Trakt does not document an equivalent read-only scope in its authorization request. Super Seerr uses these account connections to read watchlists. Saving another Client ID replaces that provider's existing local connection.

Official authentication references: [Trakt PKCE](https://developer.trakt.tv/docs/pkce), [Trakt authentication](https://developer.trakt.tv/docs/authentication-oauth), [Simkl public client setup](https://api.simkl.org/api-reference/auth), and [Simkl V2 authorization](https://api.simkl.org/api-reference/oauth2-authorization-code).

## Review a watchlist in Seerr

Choose **Sync watchlist** when you want to read your titles. Use **Load more titles** to continue the review: pages contain up to **100 titles**, with a maximum of **500 titles** in one review. Unsupported or invalid entries are skipped; a provider may also refuse or return a response too large for this import. The provider's website remains the place to view the complete list.

Trakt reads the account's movie and show watchlist. Simkl reads **Plan to Watch** entries, including anime identified explicitly as a movie or TV series. Other anime formats are skipped. This view concerns planned titles, rather than importing watched history, ratings, comments or playback activity. Simkl's API returns its watchlist data as a response rather than using Trakt-style server pagination; the review limit does not guarantee that only 500 records are downloaded.

**Find in Seerr** opens a title search in the **currently active Seerr site**. Review the result, availability and any requested seasons there, then submit a request separately. Syncing a tracker watchlist does not submit Seerr requests, add titles to Seerr's watchlist, or write changes back to Trakt or Simkl. This is a manual watchlist review, not automatic background or bidirectional synchronization.

If a request is rate limited, wait before trying again. Provider quotas may be shared with other applications connected to the same account. See [Trakt pagination](https://developer.trakt.tv/docs/pagination), [Trakt rate limits](https://developer.trakt.tv/docs/rate-limiting), [Simkl sync rules](https://api.simkl.org/guides/sync), and [Simkl rate limits](https://api.simkl.org/resources/rate-limits).

## Disconnect and storage

**Disconnect** removes that provider's access and refresh tokens from this extension's local storage and clears its watchlist preview. It retains the public Client ID so you can reconnect. It does not change the provider's watchlist or revoke the application's authorization at the provider.

To revoke that authorization too, manage connected applications in [Trakt's account settings](https://app.trakt.tv/settings) or [Simkl Connected Apps](https://simkl.com/settings/connected-apps/).

Tokens stay in local extension storage on this device and are not synchronized as browser preferences. Settings receives connection state and watchlist entries, not the tokens. Treat the browser profile as private. Account tokens and provider watchlist data are separate from public rating caches and from each Seerr site's configuration. See [Data, storage and permissions](privacy-and-permissions.md).

## JustWatch availability

Choose **Streaming region** in the flyout, then **Where to watch** to search JustWatch in that country. The selected region is saved as a browser preference. Check the provider's page for current availability, prices and the exact title.

Super Seerr does not connect to a JustWatch account or call its streaming-availability partner API. The [official JustWatch API](https://apis.justwatch.com/docs/api/) requires a partner agreement and token. The current integration reads supported title pages and opens country-specific search links.

## Verification limits

Automated tests use isolated fixtures for provider responses, sign-in callbacks and UI behavior. They do not prove that a real provider has accepted an application registration, that a user has granted consent, or that a live account can synchronize successfully. Live OAuth verification requires your registered public Client IDs, the callback shown for your installation, and your own provider account. Those steps do not require sharing passwords, client secrets or account tokens with the project.
